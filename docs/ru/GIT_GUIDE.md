# Клонирование и основы работы с Git

Git сохраняет историю изменений на твоём компьютере. GitHub хранит удалённую копию и позволяет работать совместно. Для запуска достаточно ZIP; для разработки и отправки изменений используй клон.

## 1. Получи доступ и установи Git

Репозиторий [turcinv/SOSkuska](https://github.com/turcinv/SOSkuska) **закрытый**. Сначала открой его в браузере под аккаунтом с доступом. Ошибка 404 может означать отсутствие прав.

Проверь установку Git:

```sh
git --version
```

Если команды нет, установи Git по [официальной инструкции для своей платформы](https://git-scm.com/downloads/). На Windows используй Git for Windows и сохрани Git Credential Manager; после установки открой новый PowerShell. На macOS можно использовать Apple Command Line Tools по предложению системы или другой способ из официальной инструкции. На Linux используй пакет своего дистрибутива.

При клонировании по HTTPS Git Credential Manager может открыть вход в браузере. Войди под аккаунтом с доступом. Сам вход на сайте не обязательно авторизует Git. Не вставляй пароль аккаунта в адрес репозитория; подробности есть в [документации GitHub по авторизации](https://docs.github.com/en/get-started/git-basics/caching-your-github-credentials-in-git). Если GitHub CLI уже установлен, можно использовать `gh auth login` и `gh auth setup-git`.

## 2. Клонируй проект

В терминале перейди в родительскую папку, где хочешь разместить проект. Затем выполни:

```sh
git clone https://github.com/turcinv/SOSkuska.git
cd SOSkuska
git status
```

Появится новая папка `SOSkuska` с историей `.git`. В выводе должна быть ветка `main` без несохранённых изменений. Если целевая папка уже существует, не клонируй поверх неё: выбери другую родительскую папку. Уже существующий настоящий клон обновляй через `git pull --ff-only`.

## 3. Подготовь Python и запусти приложение

Клон не содержит виртуального окружения или базы. На каждом компьютере создай собственное окружение. Если на Windows ещё нет Python, сначала пройди [инструкцию Windows с нуля](WINDOWS_FIRST_RUN.md); шаги скачивания ZIP пропусти, поскольку клон уже есть.

Windows / PowerShell, если Python 3.12 уже установлен:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r soskuska/requirements.txt
.\.venv\Scripts\python.exe soskuska/app.py --data .local-data/dev.sqlite3
```

macOS с Python 3.12 и Tk:

```sh
python3.12 -m venv .venv-macos
.venv-macos/bin/python -m pip install -r soskuska/requirements.txt
.venv-macos/bin/python soskuska/app.py --data .local-data/dev.sqlite3
```

Linux, требования к Tk и решение проблем описаны в [руководстве разработчика](DEVELOPMENT.md).

## 4. Настрой автора для этого клона

Перед первым коммитом укажи своё имя и адрес, которые должны попасть в историю. Следующие два значения — примеры: замени их своими. GitHub также предлагает частный адрес `noreply` в настройках электронной почты.

```sh
git config user.name "Твоё имя"
git config user.email "your-address@example.com"
```

Без `--global` команды меняют только этот репозиторий. Автор коммита и авторизация в GitHub — разные вещи.

## 5. Обычный рабочий процесс

Начни с чистой ветки `main`:

```sh
git switch main
git pull --ff-only
git switch -c feature/my-change
```

Измени файлы и выполни подходящие проверки из [CONTRIBUTING](CONTRIBUTING.md). Затем проверь и сохрани изменения:

```sh
git status
git diff
git add README.md
git diff --cached
git commit -m "docs: clarify setup instructions"
git push -u origin feature/my-change
```

`README.md`, имя ветки и сообщение — примеры. В `git add` укажи файлы своего реального изменения; отправляй только проверенные файлы. `commit` сохраняет историю локально, `push` отправляет её на GitHub. Для записи нужны права на репозиторий.

На GitHub открой **Compare & pull request**, выбери базу `main`, опиши изменение и действительно выполненные проверки. После проверки и слияния вернись на `main` и обнови её. Эта инструкция сама по себе не разрешает менять права доступа или видимость репозитория.

## 6. Обновление существующего клона

```sh
git status
git switch main
git pull --ff-only
```

Перед переключением и загрузкой разберись со своими несохранёнными изменениями. Если `--ff-only` сообщает о разошедшейся истории, остановись и проверь её; не добавляй вслепую `--force` и не удаляй работу через `reset --hard`.

После изменения `requirements.txt` повтори установку библиотек интерпретатором своего окружения. После обновления кода перезапусти приложение. Базы и окружения через Git не синхронизируются.

## Краткая справка

| Команда | Значение |
| --- | --- |
| `git status` | Состояние ветки и изменённые файлы |
| `git diff` | Изменения, ещё не подготовленные к коммиту |
| `git diff --cached` | Содержимое следующего коммита |
| `git log --oneline -5` | Пять последних коммитов |
| `git remote -v` | Адрес удалённого репозитория |
| `git pull --ff-only` | Получение изменений без автоматического коммита слияния |

В репозиторий отправляются исходники и документация. Виртуальные окружения, `.local-data/`, базы SQLite и `.env` игнорируются. Скачанный ZIP не содержит историю `.git`; для работы с Git начни с клонирования в другую папку.
