# Разработка и запуск

Проекта ещё нет? Начни с [клонирования и основ Git](GIT_GUIDE.md). Правила изменений описаны в [CONTRIBUTING](CONTRIBUTING.md).

Выполняй команды из корневой папки проекта. Нынешнее приложение использует скрипты в `soskuska/`, а не устанавливаемый пакет.

## Этот Mac — самый быстрый путь

```sh
cd "$HOME/Documents/SOSkuska"
.venv-macos/bin/python soskuska/app.py --data .local-data/dev.sqlite3
```

База для разработки отделена от обычных пользовательских данных. Родительский каталог создаётся автоматически, `.local-data/` игнорируется Git. Без `--data` приложение использует стандартную пользовательскую базу; это другой файл. Скрипт `soskuska/run-macos.command` принимает те же аргументы.

## Требования

Проверенное окружение — Python 3.12.13 / Tk 9.0 / CustomTkinter 5.2.2. Для воспроизведения используй Python 3.12 с Tk. На macOS приложению нужен как минимум Tk 8.6. Сама версия Python не гарантирует наличие Tk.

Внешние зависимости указаны в `soskuska/requirements.txt`. Полного lockfile пока нет, версии транзитивных зависимостей выбирает установщик. Интернет нужен один раз для установки; затем Dashboard работает offline. Ollama пока не нужна. Для GUI-проверок необходим графический рабочий сеанс.

## Новое окружение на macOS

```sh
python3.12 -c "import sys, tkinter; print(sys.executable); print(sys.version); print('Tk', tkinter.TkVersion)"
python3.12 -m venv .venv-macos
.venv-macos/bin/python -m pip install -r soskuska/requirements.txt
.venv-macos/bin/python soskuska/app.py --data .local-data/dev.sqlite3
```

На этом Mac подходящий интерпретатор также доступен по пути `/Users/turcinv/.local/bin/python3.12`. `/usr/bin/python3` использует старый системный Tk 8.5; у Homebrew `python3` при проверке отсутствовал `_tkinter`. Подавление предупреждения через `TK_SILENCE_DEPRECATION` не исправляет пустое окно.

Если окружение уже существует с другим Python, создай новое под другим именем и скорректируй команды: установка библиотек не заменяет базовый Python существующего окружения. Скрипт запуска ожидает именно `.venv-macos`.

## Windows — PowerShell

Если ещё не установлен даже Python, начни с подробной инструкции [Windows с нуля](WINDOWS_FIRST_RUN.md). Следующий сокращённый вариант предполагает уже подготовленный Python.

Предполагается установленный Python 3.12 с Tcl/Tk и средством запуска `py`.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r soskuska/requirements.txt
.\.venv\Scripts\python.exe -c "import tkinter; print(tkinter.TkVersion)"
.\.venv\Scripts\python.exe soskuska/app.py --data .local-data/dev.sqlite3
```

Активировать окружение или менять execution policy не требуется. Практическая проверка на Windows ещё не выполнена.

## Linux

Используй Python с поддержкой Tk и виртуальных окружений. Системные пакеты часто называются `python3-tk` и `python3-venv`; точные имена зависят от дистрибутива и должны соответствовать выбранному Python.

```sh
python3 -c "import sys, tkinter; print(sys.version); print('Tk', tkinter.TkVersion)"
python3 -m venv .venv
.venv/bin/python -m pip install -r soskuska/requirements.txt
.venv/bin/python soskuska/app.py --data .local-data/dev.sqlite3
```

Практическая проверка на Linux ещё не выполнена. На сервере без графического сеанса окно не откроется.

## Проверки

Синтаксис без открытия окна:

```sh
.venv-macos/bin/python -m compileall -q soskuska
```

Нативная проверка работы с собственной временной базой:

```sh
.venv-macos/bin/python soskuska/check_dashboard.py
```

На Windows/Linux замени интерпретатор на путь из своего окружения. Скрипт ненадолго открывает окно и проверяет отображаемые элементы, поиск/пустое состояние, боковую панель, компактное расположение, колесо, в Tk 9 трекпад, таймер и сохранение времени. При успехе выводит `PASS` и закрывает окно. Обычная база не используется.

В Tk предусмотрено защитное завершение через 12 секунд, но это не жёсткий лимит процесса при зависании самого цикла GUI. В таком случае заверши процесс через Ctrl+C. Проверка синтаксиса и синтетические события не заменяют ручную визуальную проверку или тест физического трекпада.

После изменения UI вручную проверь 1440 × 900 и 1024 × 700, доступность нижнего содержимого, настоящий жест/колесо, боковую панель, поиск, Ctrl+K / Cmd+K и Escape. После изменения хранения отметь задачу и заверши короткое занятие; перезапусти и проверь данные. Автоматическая перезагрузка кода не реализована — приложение нужно перезапускать.

## Решение проблем

| Симптом | Что сделать |
| --- | --- |
| Пустое окно / system Tk warning | Проверь интерпретатор и версию Tk; на этом Mac используй `.venv-macos` |
| `No module named _tkinter` | Выбери Python, собранный с Tk; одной установки CustomTkinter недостаточно |
| `No module named customtkinter` | Устанавливай requirements тем же интерпретатором, которым запускаешь приложение |
| Трекпад не прокручивает содержимое | Используй актуальный `scrolling.py` и перезапусти; Tk 9 требует `TouchpadScroll` |
| Ошибка записи SQLite | Через `--data` выбери доступный для записи путь, проверь права и свободное место |
| Нет прежних данных | Сравни `--data` с путём пользовательской базы по умолчанию |

## Дальнейшая разработка и GitHub

UI сейчас находится в `app.py`, SQL — в `storage.py`, прокрутка — в `scrolling.py`. Для изменения нативного приложения не нужно редактировать HTML-макет. Постепенное разделение описано в [планируемой архитектуре](PLANNED_ARCHITECTURE.md).

В репозиторий не должны попадать виртуальные окружения, файлы SQLite, кеш и локальные настройки инструментов. Исходники находятся в закрытом репозитории [turcinv/SOSkuska](https://github.com/turcinv/SOSkuska).

Совместимость с прежним названием: если новой базы в `SOSkuska` нет, а прежняя `ExamPrep/dashboard.sqlite3` существует, приложение использует прежний файл. Оно ничего автоматически не копирует, не перемещает и не перезаписывает. Явный `--data` всегда имеет приоритет.

Проверка хранилища без GUI, включая сохранение прежних данных:

```sh
.venv-macos/bin/python -m unittest discover -s tests -v
```


Новая интеграционная проверка также создаёт и изменяет предмет через UI, проверяет пустую базу без демонстрационных метрик, дату экзамена, связь занятия и удаление предмета с сохранением истории. Миграцию прежних таблиц и валидацию предметов проверяет `tests/test_subjects.py`. Используются только временные данные.


Интеграционная проверка теперь также проверяет реальное переключение столбцов при изменении ширины, продолжение планирования таймера после ошибки автоматического сохранения и обновление задач при смене дня. Тест одновременных миграций использует только временные базы.
