## Перед началом

Прочитай [README](README.md), [основы Git](GIT_GUIDE.md), [руководство разработчика](DEVELOPMENT.md) и [текущую архитектуру](CURRENT_ARCHITECTURE.md). Дополнительные инструкции для ассистентов-разработчиков находятся в [AGENTS.md](../../AGENTS.md).

Работай в новой ветке от актуального `main`. Одно изменение должно решать одну понятную задачу. Реализованы Dashboard, My Subjects, Question bank, Practice Tests, Flashcards, Statistics, необязательный AI Tutor и Settings; не представляй остальные будущие экраны как готовые функции. Новая база должна оставаться пустой, пока пользователь не добавит свои данные. Используй отдельную базу для разработки через `--data .local-data/dev.sqlite3`.

## Перед отправкой

На macOS с подготовленным окружением:

```sh
.venv-macos/bin/python -m compileall -q soskuska tests
.venv-macos/bin/python -m unittest discover -s tests -v
```

Для обычных проверок UI, таймера и прокрутки используй контейнер выше. Нативные GUI-скрипты открывают настоящие окна и нужны только для обязательной платформенной/ручной проверки; сначала согласуй видимый запуск с пользователем. Полный список — `GUI_CHECKS` в `tools/run_checks.py`. На Windows/Linux используй соответствующий Python, например:

```sh
.venv-macos/bin/python soskuska/check_dashboard.py
.venv-macos/bin/python soskuska/check_note_generation.py
```

GUI-проверка открывает окно и требует графического сеанса. Для изменения только документации обычно достаточно проверить ссылки, команды и форматирование; запускать весь UI ради неё не нужно.

Проверь `git diff --check` и содержимое коммита. Не добавляй виртуальные окружения, базы, кеш, токены или `.env`. Сохраняй пользовательские данные, стабильность UI и работу без интернета. При существенном изменении обновляй английскую, чешскую, словацкую и русскую документацию. AGENTS.md остаётся на английском, интерфейс приложения пока тоже.

## Pull request и сообщения о проблемах

Отправь свою ветку и открой pull request в `main`. Опиши проблему, новое поведение и действительно выполненные проверки, включая ОС, Python и Tk. Добавь снимок экрана, если он помогает оценить изменение UI. Не отмечай невыполненные проверки как успешные; синтетические события не доказывают проверку физического трекпада.

Сообщай об ошибке через шаблон в Issues: шаги воспроизведения, ожидаемое/фактическое поведение, окружение и полный релевантный вывод. Предложение функции должно описывать потребность пользователя и ожидаемое поведение. Не прикладывай частную базу или данные доступа. В Issues и pull request можно писать по-чешски, по-словацки, по-английски или по-русски.

## Непрерывная интеграция (CI)

CI: Python 3.12, модульные тесты на Ubuntu, Windows и macOS, GUI-скрипты из `tools/run_checks.py` (26 в v0.31.0) на Ubuntu/Xvfb и проверка сборки переносимой версии для Windows. [Результаты](https://github.com/turcinv/SOSkuska/actions/workflows/ci.yml). Проверки не развёртывают и не публикуют выпуски. При изменении отчётов см. [правила статистики](STATISTICS.md); самооценки нельзя выдавать за измеренное освоение материала. Изменения промптов или схемы AI нужно также повторно проверять с помощью `tools/evaluate_ai.py` на настоящей локальной модели (см. [Разработка](DEVELOPMENT.md)).

## Статистика (v0.6.0)

В меню **Statistics** выбери Last 7 days, Last 30 days или All time. Экран показывает сохранённое время и занятия, точность завершённых тестов с равным весом вопросов, число собственных оценок карточек, время по предметам и активность по дням. Refresh или возвращение на экран загружает новый снимок. Это не измерение освоения материала.
