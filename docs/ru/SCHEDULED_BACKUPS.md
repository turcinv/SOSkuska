# Локальные копии по расписанию

[English](../SCHEDULED_BACKUPS.md) · [Čeština](../cs/SCHEDULED_BACKUPS.md) · [Slovenčina](../sk/SCHEDULED_BACKUPS.md) · [Русский](SCHEDULED_BACKUPS.md)

Локальные копии по расписанию доступны в **v0.18.0**. Схема SQLite остаётся **10**. Ручное копирование и восстановление работают отдельно.

В Settings прокрутите до Daily local backups. Выберите существующую локальную папку, включите Enable daily backups и нажмите Save backup schedule (названия переводятся согласно языку интерфейса). У плана собственные сохранение и загрузка; сохранение учебной/AI формы не сохраняет план. Автоматика начинается только после явного включения и сохранения. Отключение сохранённого плана останавливает следующие автоматические копии.

Проверка идёт после запуска и примерно раз в минуту, пока приложение открыто. Отдельный процесс создаёт не более одной копии за текущий местный день. Закрытое приложение задач не запускает; после нескольких дней отсутствия создаётся одна актуальная копия. Смена папки или выключение/включение не добавляют копию после записанного успеха в тот же день. При переводе часов назад нужно дождаться дня после последнего успеха. Retry backup проверяет необходимость копии; для дополнительной ручной копии используйте Create backup.

Копируются подтверждённые данные SQLite, включая сохранённые контрольные точки занятий, в существующий самостоятельный формат копий. Несохранённые черновики и время после последней контрольной точки не включаются. Файлы не перезаписываются и не удаляются. Уникальные имена начинаются с `SOSkuska-auto-`; старые копии и свободное место нужно контролировать самостоятельно. Копии не зашифрованы и не загружаются в облако.

Для базы работает один процесс ежедневного копирования. Другое окно ждёт и проверяет снова; устаревший план не перезапишет новые настройки. Фоновая запись успеха не делает черновик настроек устаревшим. Загрузка требует подтверждения замены изменённого черновика; ошибки записи/чтения сохраняют его. Ошибка остаётся видимой после навигации. Закрытие во время задачи сохраняет страницу и черновики, показывая уведомление внизу окна. Дождитесь окончания; обычную учёбу можно продолжать.

После ошибки повтор идёт примерно через пятнадцать минут; Retry backup запрашивает более раннюю проверку. Проверьте папку, права записи и свободное место. Для процессов установлены тайм-ауты. Сбой между публикацией полной копии и записью подтверждения может оставить дополнительную исправную копию при повторе; приложение её сохраняет. Гарантии при отключении питания нет.

Местный план и запись успеха хранятся рядом с базой в `<database>.backup-plan.json`, с блокировкой `<database>.backup-plan.lock`. Запись атомарно заменяет частный временный файл; повреждённые настройки отключают автоматику до явного исправления. Не удаляйте блокировки при открытых окнах. План не входит в экспорт SQLite: восстановление на другом компьютере не включает там автоматику. Восстановление уже настроенной базы сохраняет план этого компьютера. Перенос/копирование только базы на новый путь требует повторного включения. Миграция схемы не нужна.

Разработка: `automatic_backup.py` отвечает за проверку, идентификатор плана, запись успеха и блокировку. `scheduled_backups.py` управляет интерфейсом в главном потоке и процессом с файловым выводом; `backup_worker.py automatic` работает без Tk. `tests/test_automatic_backup.py` и `check_scheduled_backups.py` проверяют сохранение, параллельные окна, ошибки, GUI и новый процесс в [контейнере](CONTAINER_TESTS.md). Windows CI проверяет встроенный помощник с Unicode-папкой; это не заменяет ручную проверку чистого компьютера и оборудования.
