# Приёмочные шаги перед v1.0.0

[English](../V1_RELEASE_PLAN.md) · [Čeština](../cs/V1_RELEASE_PLAN.md) · [Slovenčina](../sk/V1_RELEASE_PLAN.md) · [Русский](V1_RELEASE_PLAN.md)

Решение от **23 ноября 2026 года**. Перед подготовкой v1.0.0 проверить опубликованную **v0.18.1**, схема **10**. Основная реализация для текущего объёма семестрового проекта готова; доказательств ручной проверки Windows и реальной модели пока нет. План не отмечает проверки успешными и не разрешает слияние/выпуск. Приостановить новые функции на время приёмки. Отчёт и презентацию можно готовить отдельно; они не блокируют выпуск приложения.

## 1 Получить версию Windows

На Windows x64 без Python скачать `SOSkuska-windows-x64.zip` и `.sha256` из [v0.18.1](https://github.com/turcinv/SOSkuska/releases/tag/v0.18.1); нужен доступ к закрытому репозиторию. Сверить хеш и полностью распаковать ZIP в доступную для записи папку. Сохранить вместе `SOSkuska.exe`, `_internal` и `SOSkuska-worker.exe`. Следовать [переносимой версии](WINDOWS_PORTABLE.md); записать блокировку политикой безопасности, не отключая защиту.

## 2 Использовать временные данные

Открыть PowerShell в папке распакованного приложения и выполнить:

```powershell
$acceptanceDb = Join-Path $env:TEMP ("SOSkuska-acceptance-" + [guid]::NewGuid().ToString() + ".sqlite3")
.\SOSkuska.exe --data "$acceptanceDb"
```

Записать значение `$acceptanceDb`. При каждом повторном открытии выполнять только вторую строку с **тем же путём**, не создавать новый GUID. После закрытия PowerShell вернуть записанный путь в переменную. Проверять копирование/восстановление только на этой базе, закрыв остальные экземпляры перед восстановлением. Не менять обычные учебные данные.

## 3 Завершить приёмку Windows

Пройти полный [список Windows](WINDOWS_ACCEPTANCE.md), одного запуска недостаточно. Проверить пустой старт, Unicode-предметы/темы/вопросы, просмотр/импорт CSV, тесты и результаты, оценки/историю карточек, паузу/завершение занятия. Закрыть и открыть ту же базу, проверить сохранение. Для восстановления занятия прервать только временный тестовый экземпляр после контрольной точки; проверить восстановление на паузе без учёта выключенного времени и отказ от восстановления. Проверить копирование/восстановление и страховочную копию, включённые ежедневные копии при открытом приложении, языки/оформление, вложенную прокрутку, размеры 1440×900/1024×700 и поддерживаемый масштаб 100/125/150 %. Неподдерживаемые сочетания указать явно.

## 4 Проверить реальную модель Ollama

Ollama остаётся необязательной для обычной учёбы, но Tutor требует реальной проверки перед завершением приёмки. Записать версии сервера/модели, идентификатор модели, оборудование, дату и адрес без учётных данных. Явно Connect и Send; проверить поток, Stop, переподключение и открытие сохранённого чата. Остановить сервер и проверить офлайн-учёбу. Записать ограничения качества/скорости; имитация сервера в CI не доказывает работу реальной модели. Невыполненные проверки оставить NOT RUN с причиной, не объявляя приёмку завершённой.

## 5 Записать результаты

Копировать запись для каждого устройства/прогона и приложить доказательства к каждому пункту. Использовать PASS / FAIL / NOT RUN; пустое поле не означает успех. Снимки не должны содержать личные учебные материалы и учётные данные.

## 6 Устранить замечания

Исправлять ошибки в новой ветке и PR, сохранять воспроизведение, провести независимую проверку Sol с medium и нужные контейнерные проверки и CI. Повторить неудачные проверки на исправленном Windows артефакте; старый успех не подтверждает изменённое поведение. Оставить видимыми все нерешённые/непроверенные пункты. Сливать только с явного разрешения пользователя.

## 7 Подготовить v1.0.0

После успешной приёмки и исправлений согласовать версию/нижнюю подпись, четыре README-ссылки, статус архитектуры и changelog через PR. Проверить CI и получить разрешение на слияние/выпуск. Пометить точный слитый коммит, получить его проверенный Windows ZIP/хеш/отчёт из CI main и опубликовать описание с функциями, изменениями и ограничениями. Проверить тег, хеш и скачивание. Не переименовывать бинарный файл v0.18.1 в v1.0.0. План не обещает установщик, EXE для macOS, автообновление или отсутствие ошибок.
