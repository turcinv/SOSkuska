## Проект и рабочие предпочтения

SOSkúška — нативный семестровый проект на Python/CustomTkinter/SQLite. Добавляй посильные еженедельные функции и оставляй время для семестровой документации. Приложение работает офлайн; Ollama необязательна. Пользователь выбрал локальную разработку из-за платной генерации дизайна. HTML в `soskuska-local/` — визуальный ориентир.

Пользователь может переключаться между чешским, словацким, английским и русским; отвечай на последнем языке. UI остаётся английским. Основная документация — английская, переводы хранятся отдельно. Внутренние инструкции для агентов остаются английскими.

## Разработка и выпуск

1. Создай новую ветку от актуального main; реализуй запрошенный шаг плана. Никогда не коммить и не отправляй изменения прямо в main.
2. Используй временные данные, выполни подходящие проверки и для реализации функций запроси независимую проверку **Sol со средним усилием**. Исправь замечания в той же ветке и проверь исправления повторно.
3. Открой PR, опиши фактическую проверку и проверь CI. Исправляй сбои без ослабления проверок. Зелёный CI сам по себе не разрешает слияние.
4. Сливай после разрешения пользователя. Запрос на слияние и выпуск включает необходимый PR с обозначением версии и публикацию. Перед созданием тега точного объединённого коммита согласуй версию в подвале, четырёх README, заголовках changelog и состоянии архитектуры.
5. Проверь опубликованный выпуск и чистый main, синхронизированный с GitHub. Следующая функция, слияние, выпуск и удаление веток не разрешены автоматически прежней работой.

## Полезные выводы

- **Отделяй запись от повторного чтения.** После успешной записи исключи группу из повторной отправки до чтения итогов. Сбой обновления не должен повторять импорт. При неизвестном результате процесса запись уже могла завершиться; сначала проверь данные.
- **Сохраняй стабильный просмотр.** Используй отдельную группу; изменение CSV требует повторного выбора. Повторно проверь цель/имя и дубликаты под блокировкой записи, затем сохрани всё одной транзакцией.
- **Для CSV/копий используй процессы.** Сборка мусора в потоке Python ранее уничтожила объекты Tk и аварийно завершила приложение на macOS. Tk должен работать в главном потоке. Вывод процесса направляй во временный файл: непрочитанные каналы могут заблокироваться на Windows.
- **Просмотр открывает базу только для чтения.** Не создавай и не мигрируй базу при просмотре. Используй уже показанную цель; синхронный запрос при выборе файла может заблокировать Tk при занятой базе.
- **Сохраняй незавершённый текст.** Перестроение экрана может потерять неподтверждённый поиск или черновик. Храни текст отдельно от применённого фильтра и проверяй навигацию и обновление после записи.
- **Проверяй мелочи UI.** Сообщение ожидания должно попадать в активный импорт. Тест дубликата за пределом списка должен действительно создать достаточно записей.
- **Точно описывай проверенные платформы.** macOS и Linux/Xvfb не доказывают ручную работу UI Windows или физического трекпада. На подготовленном Mac используй `.venv-macos`; Apple Tk 8.5 в `.venv-desktop` показывал пустое окно.

## Компактный контекст будущих сессий

Корневой `AGENTS.md` служит кратким указателем. Перед изменением области прочитай нужные файлы `@docs/agents/...`; остальные загружай по необходимости. Это явные указания прочитать файлы, а не обещание автоматической вставки. Официальное [руководство Codex по AGENTS.md](https://developers.openai.com/codex/guides/agents-md) описывает иерархическое обнаружение инструкций; поэтому проект явно требует открывать указанные файлы.

Постоянные правила записывай в соответствующий файл инструкций, новые датированные результаты — сюда, историю выпусков — в changelog. Изменения поведения отражай в правилах и всех языках пользовательской документации.
