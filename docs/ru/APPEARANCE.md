# Настройка оформления

[English](../APPEARANCE.md) · [Čeština](../cs/APPEARANCE.md) · [Slovenčina](../sk/APPEARANCE.md) · [Русский](../ru/APPEARANCE.md)

Функция реализована в ветке оформления и **не входит в выпущенную v0.15.0**. Не сливать PR, пока пользователь не подтвердит завершение тестирования v0.15.0 и явно не разрешит слияние. Ошибки базового выпуска исправляются отдельными PR.

Открой **Settings → Appearance (applies on Save)** и выбери Light, Dark или System. Сохранение сразу применяет и запоминает выбор для этой базы. Сам выбор — черновик; навигация его сохраняет, Reload подтверждает замену. Ошибка или устаревшая ревизия сохраняют нынешнее оформление и черновик. Для прежних баз по умолчанию Dark. Сохранение всей формы по-прежнему проверяет поля и ограничения изменений AI.

Оформление независимо от языка интерфейса и ответов AI. Оно меняет существующие виджеты без перестройки экранов: не удаляет черновики редакторов/Tutor, не сбрасывает время занятия/теста, не меняет историю и не запускает сеть. Язык интерфейса всё ещё требует перезапуска. Другие окна принимают настройки при собственном Save/перезапуске, без живой синхронизации.

System следует нативному оформлению Windows/macOS и реагирует на изменения ОС во время работы. В Linux и других неподдерживаемых системах намеренно используется Light, чтобы закреплённые зависимости не запускали детекцию подпроцессами в потоке Tk. В Linux можно выбрать Light/Dark явно. Реакция System проверяется имитацией уведомлений ОС; ручные нативные/DPI проверки учитываются отдельно.

`theme.py` содержит парные цвета поверхностей, текста, элементов, меню, подсказок, отключённых основных кнопок и удаления. `appearance.py` использует публичный API CustomTkinter. Проверки оценивают контраст видимого текста и фона на экранах; они не доказывают полную доступность или ручную платформенную проверку.

Схема **9** добавляет `preferences.appearance_mode` со значениями Light/Dark/System и исходным Dark. Миграция сохраняет содержимое, беседы, языки и ревизию; ошибка откатывает изменения. Выбор входит в резервные копии. Эта ветка восстанавливает отдельные копии схемы 9; старую доверенную копию можно мигрировать открытием при запуске и затем экспортировать заново. Сохрани оригинал: v0.15.0 использует схему 8 и не откроет данные схемы 9.

Для параллельного тестирования используй новую временную базу `--data .local-data/appearance.sqlite3` или отдельную копию. Не мигрируй базу приёмки v0.15.0 сборкой функции. [Приёмка Windows](WINDOWS_ACCEPTANCE.md) по-прежнему относится к выпущенной базе.

Проверки: `tests/test_appearance.py`, `soskuska/check_appearance.py`, сохранение потока в `check_tutor.py`, элементы на четырёх языках и запуск Windows-пакета во всех 12 сочетаниях языка/оформления. GUI по умолчанию в [контейнере](CONTAINER_TESTS.md). Новая зависимость приложения не нужна.
