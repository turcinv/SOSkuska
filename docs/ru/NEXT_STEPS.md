# Следующие шаги · 22 ноября 2026 года

[English](../NEXT_STEPS.md) · [Čeština](../cs/NEXT_STEPS.md) · [Slovenčina](../sk/NEXT_STEPS.md) · [Русский](../ru/NEXT_STEPS.md)

Текущий выпуск: **v0.18.1**, схема **10**, с сохранённым Light/Dark/System. Пользователь 22 ноября подтвердил завершение проверки v0.15.0 и разрешил слияние оформления; условие выполнено. Подтверждение не заменяет результаты для отдельных устройств: подробности чистого компьютера, DPI и оборудования не представлены. Разделяй их в доказательствах проекта.

1. **Проверить новый выпуск.** Использовать временные данные или копию резервной базы. На Windows проверить живое Light/Dark, черновики, четыре языка, компактное окно и масштаб. System проверить настоящим изменением ОС на Windows/macOS; Linux намеренно использует Light. Экспортировать и открыть копию схемы 10. Сохранить оригиналы схемы 9: v0.16.0 не откроет мигрированные данные. Записать [приёмку Windows](WINDOWS_ACCEPTANCE.md).
2. **Проверить реальную модель Ollama.** Записать ОС, оборудование, модель/версию, адрес сервера и результаты подключения, потока, Stop, переподключения и сохранённого чата. Учебные функции должны работать с остановленным сервером. Имитация в CI не доказывает качество модели или производительность оборудования. Реальная проверка пока не записана.
3. **Параллельно готовить семестровую сдачу.** Описание реализации, диаграммы архитектуры, снимки, доказательства тестов, ограничения и сценарий демонстрации. Различать выпущенное поведение, подтверждение пользователя, автоматизацию и непроверенные ручные пункты. Перед сдачей опираться на реальные указания задания; этот список не утверждает их выполнение.
4. **Восстановление занятия после сбоя** — v0.17.0 добавляет восстановление занятия после сбоя со схемой **10**. Сначала сделайте резервную копию: миграция транзакционная, но v0.16.0 не откроет базу схемы 10. [Восстановление занятия после сбоя](FOCUS_RECOVERY.md).

Ошибки базового выпуска идут в отдельные исправляющие PR и при необходимости патч-выпуски. Функции требуют своей ветки, контейнерных GUI-проверок и независимой ревизии Sol со средним усилием. Поддерживать четыре языка документации. Слияние и публикация — только с разрешения пользователя. Новое постоянное условие тестирования базового выпуска для будущих задач не вводится автоматически.

5. **Локальные копии по расписанию** — Локальные копии по расписанию доступны в **v0.18.0**. Схема SQLite остаётся **10**. Ручное копирование и восстановление работают отдельно. [Локальные копии по расписанию](SCHEDULED_BACKUPS.md).
