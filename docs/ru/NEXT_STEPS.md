## Рекомендуемый порядок

1. **Нативная визуальная приёмка v0.29–v0.30.1.** Дизайн и панели AI пока проверены только по снимкам из Linux/Xvfb.
   - На Mac и, по возможности, на ПК с Windows при масштабе 100 % и 150 % используйте временные данные (`--data .local-data/acceptance.sqlite3`).
   - Проверьте Light/Dark, четыре языка, 1440 × 900 и 1024 × 700, сворачивание боковой панели, баннер на Dashboard и **Создать с помощью AI** в колоде и в банке вопросов.
   - Запишите ОС/сборку, масштаб и находки в [список Windows](WINDOWS_ACCEPTANCE.md). Проблемы исправляйте через проверенные PR.
2. **Более широкая проверка AI.** Повторно запустите `tools/evaluate_ai.py` как минимум с одной ещё моделью (например, `llama3.2:3b`), с длинными заметками и 20 элементами. Сравните с записью от 26 ноября. Tutor с потоковой выдачей/Stop/переподключением/историей на настоящей модели по-прежнему требует ручной проверки.
3. **Демонстрация преподавателю и семестровый отчёт.**
   - Подготовьте короткий сценарий демонстрации: создать предмет, создать вопросы из заметок, потренироваться, повторить карточки, открыть Статистику.
   - Обновите снимки экрана на временных данных.
   - Данные об имени, курсе, языке и сроке оставьте заполнителями до получения и проверьте итоговую разбивку на страницы.
4. **Стабилизировать стартовую проверку GUI в хостинговом CI.** 27 ноября `check_studio_layout.py` на машинах GitHub превысил 7-секундный предел свежего процесса, в том числе на коммите в `main`, менявшем только документацию; при повторе прошёл. Сократите работу при запуске или измеряйте его так, чтобы нагрузка хостинговых машин не ломала проверку. Не просто увеличивайте предел.
5. **Этап 2 MCP-сервера.** Сервер через stdio с необязательной закреплённой зависимостью `mcp`, тесты, настройка CI/контейнера, руководство пользователя на четырёх языках и записанный запуск с настоящим MCP-хостом. См. [план](../agents/MCP_SERVER_PLAN.md).
6. **Уборка.** Удаляйте слитые удалённые ветки только по прямому запросу; сохраняйте `main` и теги выпусков.

Перед v1.0.0 устраните находки приёмки через проверенные PR и повторите соответствующие проверки. Новая работа, слияние и публикация требуют отдельного разрешения. Это обновление статуса не отмечает ни один ручной результат как пройденный.
